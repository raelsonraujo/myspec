## Definition

Share of production lines and branches executed by the tests, per file, class, and assembly.

## Execution Context

- Working directory: repository root
- Restore or bootstrap command: `dotnet restore {{solution}}` followed by `dotnet tool restore`
- Prerequisite commands: None; the measurement command restores, builds in Release, and runs the tests before reporting
- Version source: `coverlet.collector` and `Microsoft.NET.Test.Sdk` package references in each test project; the local tool manifest (`dotnet-tools.json` or `.config/dotnet-tools.json`) for ReportGenerator
- Shared run: one execution of `my-specs/measurement/run-coverage-report` measures this metric, Cyclomatic Complexity, CRAP Score, and Module Size; run it once when measuring more than one of them

## Measurement

- Test runner: VSTest through `dotnet test`
- Tool: `coverlet.collector` (`XPlat Code Coverage` data collector), aggregated by ReportGenerator
- Version: `coverlet.collector` `6.0.4` and `Microsoft.NET.Test.Sdk` `17.14.1`, pinned in each test project; ReportGenerator `5.5.10`, pinned in the local tool manifest
- Installation or restore: follow `my-specs/measurement/README.md`, then `dotnet restore {{solution}}` and `dotnet tool restore`
- Measurement command: `pwsh -NoProfile -File my-specs/measurement/run-coverage-report.ps1 -NoOpen` or `bash my-specs/measurement/run-coverage-report.sh --no-open` (restore, build, test, and report in order), which run:
  - coverage: `dotnet test {{solution}} --configuration Release --no-build --filter "FullyQualifiedName!~.ArchitectureTests." --settings my-specs/measurement/coverlet.runsettings --collect:"XPlat Code Coverage" --results-directory my-specs/measurement/coverage/raw`
  - report: `dotnet reportgenerator -reports:"my-specs/measurement/coverage/raw/**/coverage.cobertura.xml" -targetdir:"my-specs/measurement/coverage/report" -reporttypes:"Html;JsonSummary;Cobertura"`
- Output format: Cobertura XML with line and branch coverage; JSON summary; HTML
- Result path:
  - raw: `my-specs/measurement/coverage/raw/**/coverage.cobertura.xml`
  - merged: `my-specs/measurement/coverage/report/Cobertura.xml`
  - summary: `my-specs/measurement/coverage/report/Summary.json`
  - HTML: `my-specs/measurement/coverage/report/index.html`
- Scope: every non-test assembly instrumented by at least one test project in `{{solution}}`, measured by every test project in `{{solution}}`
- Exclusions: test assemblies `[*.Tests]*` and `[*.xUnit.*]*`; `**/bin/**`, `**/obj/**`, `**/Migrations/**`, `**/*.g.cs`, `**/*.Designer.cs`, `**/*.generated.cs`, `**/AssemblyInfo.cs` (see `my-specs/measurement/coverlet.runsettings`)
- Changed-code isolation: filter the merged Cobertura report by the production paths listed in `my-specs/specs/<spec-name>/file-tree.md`, and report affected-project totals alongside the changed-file values
- Reported values: line coverage and branch coverage, with percentage and covered over total

## Decisions and Tradeoffs

- Collect coverage with Coverlet's data collector in the regular test run: no separate instrumentation step or global tool is needed.
- Pin ReportGenerator as a repository-local tool: developers and CI use the same aggregation behavior without a global installation.
- Exclude migrations and generated files: their generated volume would distort developer-controlled coverage.
- Define no coverage gate: coverage risk is judged per method through the CRAP Score gate instead of a project-wide percentage.
